# Implementation-Roadmap-Critical

**Категория**: #topic/roadmap | #topic/risk-management  
**Статус**: active

## 📖 Определение
Пошаговый план развёртывания системы "Дневник инвестора" с учётом критических предупреждений по архитектуре, ML и безопасности. Основа: ответ QWEN + методология Karpathy Wiki.

##  Зачем нужно
- Избежать типичных ошибок: иллюзия ML-автопилота, некорректный XIRR, шумные метки, уязвимости облака
- Обеспечить поэтапную разработку: от ядра → к аналитике → к ML
- Зафиксировать архитектурные решения в wiki до написания кода

## 🔧 Как работает (Пошаговый план)

| Этап | Задача | Критерий готовности |
|------|--------|---------------------|
| 1 | Развернуть локально: PostgreSQL + FastAPI + Streamlit/React UI | БД работает, API отдаёт 200, UI отображает пустую таблицу |
| 2 | Реализовать ядро: `transactions` + `cashflows` → корректный XIRR/TWRR + сравнение с MOEX | Расчёт совпадает с Excel/брокером на тестовых данных |
| 3 | Написать парсеры под 2 брокера + валидацию + ручной маппинг | Импорт CSV без потерь, fallback на ручной ввод |
| 4 | Собрать `ml_features`, натренировать LightGBM, добавить SHAP | Модель валидирована через TimeSeriesSplit, SHAP объясняет веса |
| 5 | Решить: оставить локально, переехать на RU-VPS или подключить трекер для мобильного просмотра | Архитектура зафиксирована в [[Deployment-Options-Investor-Diary]] |

## ⚠️ Критические предупреждения (Жёсткая критика)

| Риск | Почему опасно | Решение |
|------|--------------|---------|
| ML как автопилот входа/выхода | <500 сделок, шум, метки смешаны с макро-удачей | Использовать ML только как "скоринг идеи". Всегда накладывать rule-based фильтры |
| Тег "эмоционально" | Субъективная самооценка → noise в данных | Заменить на измеримые прокси: отклонение от плана, размер >X%, отмена стопа, торговля после серии убытков |
| XIRR/TWRR "по снимкам" | Искажения из-за вводов/выводов | Вести строгий `cashflows` лог. XIRR по потокам, TWRR цепочкой подпериодов |
| Импорт CSV из брокеров | Разные форматы, кривые даты, вложенные комиссии | Писать адаптер-слой с валидацией. Не один парсер под всё |
| Безопасность < удобства | Хранение ключей/сделок в облаке без шифрования = цель №1 | Шифровать БД/ФС, бэкапы 3-2-1, отключить внешний доступ к админке, WireGuard для VPS |
